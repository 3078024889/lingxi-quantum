【三、orders表和life_map_submissions表对不上——这个我加了一列来解决】
supabase/schema.sql、app/api/pay/create/route.ts、
app/life-map/LifeMapFlow.tsx
- 你复制的那个"ff078b79-..."，是 orders 表自己的行ID，不是
  life_map_submissions 表的ID——这是两张完全不同的表，各自的ID互不
  相通，生命图谱报告页面 /life-map/full?id= 后面要接的，必须是
  life_map_submissions 表里的ID，不是orders表的。这也是为什么你复制
  那个ID去访问，会提示"找不到这份提交记录"——不是bug，是从一开始就
  拿错了表的ID。
- 这次从根源上解决：给 orders 表新增了一列 submission_id，以后每次
  生命图谱报告付款下单时，会自动把对应的 life_map_submissions.id
  存进这一列——以后你在 orders 表里，直接就能看到这笔钱对应的是
  哪一份报告，不用再去猜、也不会拿错表的ID。
- 名字的问题：life_map_submissions 表本身是有 name 这一列的（你之前
  应该是在看这张表，能看到名字）；orders 表设计上就没有name这一列
  （订单表不需要认名字，认的是user_id和金额）——不是名字"消失"了，
  是你现在点开的是另一张表。以后想找报告，直接去 life_map_submissions
  表，或者用第四条说的"我的生命图谱报告"列表最省事。

【部署前必做】
═══════════════════════════════════
在 Supabase 的 SQL Editor 里手动跑这一条（新装的项目直接跑完整的
supabase/schema.sql 也可以，这条已经包含在最新的 schema.sql 里了）：

alter table public.orders add column if not exists submission_id uuid references public.life_map_submissions(id) on delete set null;

不跑这条，orders表插入新记录时不会报错（这一列允许为空），但也不会
有"对应报告"这个信息，等于白改。
