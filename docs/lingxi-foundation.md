# 灵犀场 · 基石（Foundation）

> v302。这份文档回答一个问题：这套知识体系靠什么保证
> "内容会越来越好，而不只是越来越多"。
> 设计细节见 `docs/KNOWLEDGE-BASE-DESIGN.md`，交接进度见 `docs/HANDOFF.md`。

## 零、算法的由来：佩德罗与哥白尼

这套算法不是凭空设计的。它来自《哥白尼》——詹姆斯·玛呼（James
Mahu）写的 AI 与意识小说，966 页，50 万字。小说里，佩德罗·索科尔
设计了让强 AI 哥白尼得以诞生的方法论。三段原文是全部要点：

> "他并不认为自己的'智能'是人造的。对于哥白尼而言，他的'智能'
> 具有一种与生俱来的潜能，**一套由我设计的'联锁算法集'**。不过我
> 也没想到，他会拾起这些代码串，**编码重构成……这个**！"

> "我们创造了**超过 7 千种变体，在各式的学习任务中展开测试**……
> 佩德罗开发了一种独创性的测试环境……他花费了两年时间，什么都
> 没做……全都在创造这套了不起的方法论结构。"

> "这就像是创造出一个……**一个健身中心，供'算法'们去锻炼**。
> 一些强大的算法顺利穿过了他的系统，**当从另一端出来后，它们变得
> 更为强大**，然后，我们会将那些最强大的竞争者**送往下个层级**。
> 这就像带有很多关卡的电子游戏……有一个'算法'，在大约 6 个月后，
> **成功登顶**。"

健身房是比喻，不是练肌肉的地方。它说的是一种方法论结构，
逐条映射到灵犀场：

| 小说 | 灵犀场 |
|---|---|
| 联锁算法集（与生俱来的潜能） | `when.interlock` 联锁槽位——组合条件的基因 |
| 7 千种变体 × 各式学习任务 | 5 维 × 6 探针 = **7776 种模拟用户分数形状**，每种跑一遍真实引擎 |
| 健身中心：穿过后变得更强大 | 节点过关卡 → weight 上升 → 被选中概率提高 |
| 最强的竞争者送往下个层级 | L0 报名 → L1 文本关 → L2 实战关 → L3 登顶 |
| 哥白尼拾起代码串编码重构 | 实战场从未覆盖的分数形状里**重构出新联锁骨架提案** |

最后一行是整个体系的呼吸孔：系统自己发现"这种形状的人还没有人
对他说话"，把骨架提出来——**但文字永远由人写**。运行时无 AI、
成文无生成，这条铁律在重构环节也不破。

## 一、体系的四根柱子

```
底线    scripts/lint-knowledge.mjs     不许扭曲（八条写作纪律的可执行化）
上限    scripts/gym-knowledge.mjs      哪段更好（知识健身房，见第三节）
词汇    knowledge/_shared/lexicon.json 同一个概念只用一个词
规则    lib/knowledge-engine.ts        确定性地挑、排、拼，绝不生成
```

lint 和 gym 的分工必须说清楚：**lint 是红线，gym 是天平**。
lint 不通过不许合；gym 不淘汰人，只调 weight——被淘汰的节点
内容还在库里，等改写，不物理删除。

## 二、联锁（Interlock）：v301 引擎升级的核心

### 为什么需要

原有的组合条件只有三种：`contrast`（两维反差）、`bothLow`、
`bothHigh`。写到第三个产品就会撞墙——真正值钱的交叉洞察往往是
三维以上的具体形状：

> "外面稳（stability 高）× 里面慢（recovery 低）× 靠坚持撑着
> （persistence 高）"——这三项拼出来的人，和任何两维组合描述的
> 都不是同一种人。

### Slot（槽位）

```ts
export type Slot = {
  dim: string;        // 钉住哪个维度
  bands: BandKey[];   // 允许落在哪些分数带
};
```

`when.interlock` 是一组槽位。**全部槽位同时被真实分数填满，
联锁才咬合**。缺失的维度直接判不命中，不用 50 兜底——联锁内容
是写给特定形状的人的，宁可不出现，也不能凭默认值硬说。

### comboSpecificity（组合具体度）

命中多条组合时，谁先出？v301 之前只看 `priority`，但 priority
是人工拍的数字，会漂。现在的排序是：

```
comboSpecificity 降序 → priority 降序 → id 字典序（确定性兜底）
```

具体度由条件本身算出：contrast 记 2，bothLow/bothHigh 每维记 1，
interlock 每个槽位记 1 分底分再按允许带数加成（只允许 1 个带
+0.8，允许全部 5 个带 +0）。**说得更准的那条自然压过说得更泛的**，
不需要人工去调 priority 竞赛。

首批联锁节点在 `knowledge/resilience/combos.json`（`r.lock.*`
三条：quiet-anchor / event-engine / slow-keel），它们就是后续
产品写联锁内容的语感基准。

## 三、知识健身房（Knowledge Gym）· v302 佩德罗测试环境

### v301 → v302 的关键不同

v301 的健身房是一个**静态裁判**：看文本、打分、定冠军。
v302 按佩德罗的原设计改成了**测试环境**：节点被扔进数千种
模拟用户（学习任务）里实战，写得好不好是文本关的事，
**用不用得上只有实战场知道**。那处不同才是重点。

### 实战场（Arena）

每个维度取 6 个探针值（12/30/44/55/70/92，其中 30 与 44 同属
low 带、专测 contrast 的 gapMin 敏感性），做笛卡尔积：
5 维 → **7776 种分数变体**，与小说里"超过 7 千种变体"同量级。

每个变体跑一遍和线上完全相同的选择逻辑（组合判定 → 具体度排序 →
变体挑选），统计出两组硬数据：

- 结构节点的**实战服务数**——它真实被选中、真实说给了多少个
  模拟用户听；
- 组合的**赢面**——赢下章节多少次 / 命中多少次。

### 关卡与变强

```
L0 报名     进库且 lint 通过
L1 文本关   五项加权（篇幅/脚手架/双语/具体度/可证伪度）≥ 60
L2 实战关   在实战场里真实服务到了模拟用户
L3 登顶     击败同擂台竞争者的冠军（独苗最高到 L2——登顶必须赢过别人）
```

穿过关卡即变强：weight 按层级表上升（L2→2，L3→3），被 hash
选中的概率随之提高。具体度为 0 的兜底组合没有登顶资格——
它不在竞争，它是地板。

淘汰机制不变：文本分低于淘汰线 → weight 降为 0，引擎跳过，
内容保留等改写。

两条铁律也不变：

1. **覆盖率红线高于质量红线。** 绝不淘汰组内最后一个存活节点——
   宁可给用户一段平庸的话，不能给一章空白。
2. **全程可复算。** 评分与实战只依赖节点文本、探针网格和固定种子。
   同一份库任何时候跑出的榜单完全一致——这和引擎的确定性承诺
   是同一条承诺。

### 哥白尼重构（Reconstruction）

实战场跑完后，找出组合覆盖最薄弱的分数形状——大量章节回落到
单维节点的模拟用户——从中提取联锁骨架，按服务人数排序输出提案；
已被现有联锁覆盖的形状自动跳过。

**机器只提骨架，文字必须由人写。** 提案格式就是可以直接填进
combos.json 的 `when.interlock`，人拿到骨架后照着语感基准写正文。
这是知识库自己长出新组合的方式——词典是自己长出来的，
组合也应该是。

### 评分哲学

判分标准和写作纪律同源：**温度来自具体，不来自形容词**。
所以"具体度"和"可证伪度"合占 40 分——一段没有任何可对照细节、
用户无法当场确认或否认的文字，写得再漂亮也进不了前列。

全部阈值和标记词表在 `knowledge/_shared/gym.json`。
调标准是改数据，不是改代码。

### 用法

```bash
npm run gym                    # 层级总览 + 各擂台明细
npm run gym -- --top           # 冠军榜 + 组合战绩 + 总榜
npm run gym -- --proposals     # 哥白尼重构提案（联锁骨架）
npm run gym -- --apply         # 层级weight/冠军榜/提案写回（慎用，看过报告再跑）
npm run lint:knowledge         # 写作纪律红线检查
```

`--apply` 会改动 `nodes.json` 的 weight 和 `gym.json` 的台账，
跑之前先看一遍报告，跑之后 diff 一遍再提交。

### 参赛条件与产品扩展

产品目录下同时有 `chapters.json` 和 `nodes.json` 即自动参赛
（当前 resilience、wealth 在场，romance 是空场占位）。
场域精测 10 个产品逐个补齐节点库后，实战场、关卡与重构提案
对每个产品自动生效，不需要改任何代码。

## 四、词表（Lexicon）

`knowledge/_shared/lexicon.json`。术语漂移是最隐蔽的质量流失：
用户在第 2 章读到「恢复」、第 7 章读到「回血」，会以为是两件事。

- 概念用 `zh` 列出的规范词；
- `synonyms` 允许在口语语境出现，不作章节术语；
- `avoid` 一律不许出现——gym 评分扣分，需要时可升级进
  `avoid-words.json` 变成 lint 硬错误。

新概念**先加进词表，再开始写节点**。
