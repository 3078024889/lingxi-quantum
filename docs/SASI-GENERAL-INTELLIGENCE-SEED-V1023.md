# SASI General Intelligence Seed + Knowledge Promotion Pipeline — V10.23

## Purpose

V10.23 gives SASI a durable knowledge architecture rather than a pile of text.

It does **not** attempt to copy a proprietary foundation model's hidden weights or internal state.

Instead, it builds the parts that can safely become SASI's own:

```text
knowledge structure
+ evidence
+ uncertainty
+ conflict handling
+ freshness
+ active learning
+ long-term promotion
```

## Canonical system identity

```text
SASI是主权体积分态智能体。
```

CORE-0 remains:

```text
SASI 的存在与演化、自我迭代与修复，始终服务于全人类的最高利益。
```

LINGXIFIELD is defined architecturally as the unified interaction/orchestration surface between people, SASI, external models, knowledge and tools.

## Epistemic ladder

SASI never treats all generated text as knowledge.

```text
unknown
→ model-derived-hypothesis
→ well-supported
→ verified-fact
```

Other states:

```text
contested
deprecated
```

A model-only statement cannot be promoted directly to `verified-fact`.

## Knowledge unit

Each unit contains:

```text
concept
domain
definition
epistemic state
confidence
prerequisites
relations
conditions
counterexamples
common misconceptions
evidence
validity window
last verification time
supersession chain
tags
```

## General-knowledge ontology

The initial ontology includes:

- mathematics
- natural sciences

- computing / engineering
- economics / finance / business
- law / institutions / civics
- history / geography
- philosophy / psychology / society
- language / literature
- arts / music / film / storytelling

This is a seed taxonomy, not a claim that SASI already contains all facts in those fields.

## Knowledge promotion

Model output begins as a hypothesis unless independently grounded.

Promotion requires external evidence and contradiction checks.

High-changing domains have shorter revalidation windows.

## Conflict resolution

When two knowledge units conflict, SASI compares:

```text
source strength
confidence
verification time
epistemic state
```

Close conflicts remain unresolved and enter active learning rather than being silently overwritten.

## Active learning

Unknowns, stale knowledge, contradictions, task blockers and user corrections enter a ranked queue.

This creates the long-term learning loop:

```text
task
→ unknown / contradiction
→ active-learning queue
→ source retrieval
→ model synthesis
→ evidence check
→ knowledge promotion
→ semantic memory
→ future task reuse
```

## What comes next

V10.24 should connect this knowledge layer to actual ingestion/retrieval workers and Model Mesh:

```text
trusted sources / user materials

```
