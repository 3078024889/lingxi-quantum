# 全球 SIAI 排行榜：十万级资料可扩展架构（设计基线，未部署数据库）

2026-11-04 · 对应用户反馈与 PR #159。**本文件是增量扩容计划，不表示十万条已采集或生产实现。**

## 今天的真实状态
- 已批准且被 SEO 视为正式商品：32 项。另有 30 项明确标成 `source_preview` 的资料预览；页面一共 62 项，并非 62 家已验收公司。
- B001–B005 各 10 项（合计 50）公司候选仍处于 `visibleToPublic:false` 且尚未审核；不能通过分页/搜索将候选混入正式榜单。
- 数据映射保留公司、法定实体、创始人（及项目原作者的角色区别）、上市状态、成立年份、官方来源、收费、地区、支付、商业授权、审核日期；展示层不得删除任何已具备证据的事实。
- 现在 62 项仍可按 20/50/100 条在客户端快速筛选；默认一页最多 100 条，主体随整页自然向下滚动。禁止一次性预加载十万条到前端。

## 超过 500 项时的服务端读取边界
- 切换为服务端真实筛选、分页和计数（先完成独立 staging 验证再切流量）；客户端收到的字段只包含当前页最多 100 项和必要的定位游标。
- 数据模型按 `company` / `product` / `product_model` / `price_evidence` / `region_terms` / `publisher_claim` / `audit_history` 分离，稳定 `company_id`、`product_id`，不得混淆厂商和工具数。
- 数据审批模型：`candidate → verified → published → archived`；只有审核同意、来源仍有效且 `visibility = published` 的正式记录进入公开目录。来源预览另有明确标注、独立授权、独立搜索策略。
- 每条关键事实保存来源 URL、核查日期、原币种/价格单位、地区适用范围、审核人及修订版本；展示源字段的 hash/缺省语义清晰，不填造假值。

## 十万级数据库索引与查询
- PostgreSQL 索引：已发布行上的 `(sort_key, product_id)` 复合部分索引，必要的 `(category,sort_key,product_id)` / `(company_id,product_id)`；经过证据审计的搜索词采用受控全文或 trigram 索引，中文和九种语言分词分别验证。
- 首选 **键集游标分页**（例如 `WHERE status='published' AND (sort_key,id) > ($last_sort,$last_id) ORDER BY sort_key,id LIMIT 101`），使用多取一条判定是否还有下一页。这样不会对第 1000 页进行大 OFFSET 扫描。
- 前往指定页数是用户需求，但数据库查询应优先使用游标跳转、带索引的锚点和小规模页码窗口；不得将十万条一次性传送到客户端计算页码。总量显示可从预先维护的公开记录计数表读取。
- 筛选条件（任务、地区、付款、免费方案、厂商、商用）在服务端白名单解析为参数化查询，不把用户传入的任意字段名、排序表达式拼接进 SQL。
- 高并发与更新：按筛选参数+游标+目录版本缓存当前页，发布/撤回时使缓存失效；审查 API 响应尺寸和 100 条上限，慢查询用 EXPLAIN ANALYZE 验证。仅在经过统计证明需要时评估分区/搜索引擎，不为十万级先做过度架构。

## 数据权限与可复现实验
- 管理员审批与公开检索彻底分权；对暴露的 Postgres 表启用 RLS，任何公开读取只返回已发布的字段及允许展示的预览。服务端私密密钥不进入浏览器代码。
- 测试必须覆盖：0、1、20、50、100、101、100001 条数据；分页边界和排序重复值；搜索/筛选准确性；审核撤回后缓存立即失效；恶意 query 参数；九语言显示。
- 建立 100k 合成数据压测，记录数据库实际版本、机器、索引、查询计划、P50/P95/P99、错误率及成本；不能以合成压力测试冒充十万家真实公司已经收录。
- 用户体验：默认整页浏览、可选可拖动高度窗口、顶部横向条、固定平台名称列、每页 20/50/100 条、前后页/指定页、筛选条件持久化。所有已收录公司资料与来源均有可见入口。

## 正式启用门禁
当前 PR 仅恢复 62 条目录的数据完整展示和最多 100 条前端分页。服务端迁移、十万级资料导入和官方证据审核必须另立工作流，经过安全、真实数据读取、桌面手机、性能、SEO和生产回滚验收，再替换目录读取实现。无需为了这次 UI 修复变更生产数据库。
