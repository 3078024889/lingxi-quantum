# SASI：Seedance 接入、轻量存储与通识评估

核验日期：2026-09-20。本文中的产品建议不是已经上线的功能。没有提交仓库、购买服务或运行付费生成。

## 产品方向与用户痛点

海外创作者讨论中反复出现人物/服饰漂移、镜头无法衔接、为了重试消耗积分、素材和版本难找。这是定性线索，不是有代表性的全球用户统计。

- [创作者分享一年制作经验](https://www.reddit.com/r/aifilmmaking/comments/1v7hm7e/everything_ive_learned_after_1_year_of_ai/)：先确认角色、场景与叙事，再生成镜头。
- [连续性何时成为瓶颈](https://www.reddit.com/r/aifilmmaking/comments/1w3st84/at_what_point_does_continuity_become_the_real/)：衣袖破损等状态变化也需要版本化参考素材。
- [Motion by Queries 研究](https://arxiv.org/abs/2412.07750)：人物身份与运动控制存在耦合，跨镜头一致性仍需要专门方法。不能把“加入角色提示词”当成绝不漂移的保证。

建议：一个创作入口，幕后分镜；角色卡和场景图绑定镜头；生成前显示规格、参考图、预计费用；只重做选中的镜头；完成后统一成片与版本记录。普通用户不用理解节点、模型参数和任务队列。

待完整能力验收后可采用的文案：

- 首页：**把你的故事，变成能看的短剧。**
- 输入提示：**写下故事，或上传剧本。角色和场景有参考图，也一起带来。**
- 预算：**先看这次要花多少，再决定开拍。**
- 复用：**人物、场景只设一次，下一幕接着用。**
- 修改：**只改这一幕，满意的镜头保留下来。**
- 书本智能体：**让这本书，帮你完成一件事。** 子说明：带着原文解释问题，把方法变成可检查的行动步骤。

当前页面继续明确只开放了什么，不能提前把完整成片、自动部署、书本方法执行写成已开放。

## 供应商与付款

先接国内火山引擎，保留多供应商架构，不依据“最厉害”营销判断固定模型。用户通过保险箱连接自己的 API，火山直接计费；SASI 的充值和账单独立，不能把火山预估当成 SASI 扣费。

实现位置：`lib/sasi/seedance-byok.ts`、`app/api/sasi/byok/video/route.ts`、`app/sasi/SeedanceStudio.tsx`。固定北京官方 API 源，不接受任意用户 endpoint。服务端解密当前用户凭据，报价绑定项目记忆版本、凭据指纹与价格版本；确认用数据库状态原子抢占；超时保留不确定状态，不自动重复提交。

本轮范围是单镜头文生视频。图片参考、视频拼接、结果持久归档尚未完成；供应商结果链接可能过期。真实 API Key、已开通模型与价格证据缺失，生产开关保持关闭。API 连接健康测试不等于指定视频模型有权限或可成功生成。

启用前需完成：

1. 在安全表单保存用户火山 API Key，验证模型权限，绝不发到聊天或写入 Git。
2. 以[官方创建文档](https://www.volcengine.com/docs/82379/1393047)和[官方价格说明](https://www.volcengine.com/docs/82379/1544106)核对实际模型、时长、分辨率、音频支持与费用。此次官方文档网页抓取失败，因此没有编造价格或模型默认值。
3. 配置服务端 `SASI_BYOK_SEEDANCE_PROFILE` JSON：`model`、`resolution`、`generateAudio`、`maxDuration`（4–12）、`estimatedFenPerSecond`（整数分/秒、审阅过的估算）、`validUntil`、`priceSource`（官方文档 HTTPS）。没有有效资料就拒绝报价；这是估算，不是供应商硬性扣费封顶。
4. 在受控验收环境启用 `SASI_BYOK_VIDEO_ENABLED`，经用户确认运行一个最小真实任务，核对返回结果和火山账单；正式开放前补齐所承诺的素材和交付链。

## 免费存储与成本

| 服务 | 官方免费额度 | 不能忽略的限制 |
| --- | --- | --- |
| Supabase Free | 文件存储 1GB；数据库 500MB | 当前项目单文件上限实测 50MiB，不能靠改页面支持 1GB 单文件 |
| 腾讯云 COS 中国站 | 新个人用户 50GB，新企业用户 1TB；6个月 | 仅标准存储容量，请求、外网下载等另计；到期收费 |
| 阿里云 OSS | 新用户 20GB/3个月，外网流出 2GB/3个月，请求 20万次/3个月 | 须符合实名认证、尚未开通 OSS 等条件；到期或超额收费 |

来源：[Supabase 价格](https://supabase.com/pricing)、[腾讯免费额度](https://cloud.tencent.com/document/product/436/6240)、[腾讯官方计费示例](https://cloud.tencent.com/document/product/436/6241)、[阿里 OSS 免费额度](https://help.aliyun.com/zh/oss/free-quota-for-new-users)。国际站与国内站权益可能不同，以账号实际领取为准。

推荐继续保留 Supabase 登录、权限、项目、任务与账本，把大文件接入已有国内云账号的私有对象存储。不为大文件单独强制购买 Supabase Pro。

“只存一次”是文件副本数量，不是一次性付费：文件只上传一次，后续同一账户内的项目引用同一份对象；存储仍按占用时长计费，播放/下载可能产生流量费。人物图片、剧本和每次生成的视频是不同对象。1GB 视频被完整下载100次，未计缓存时约100GB流出，不是1GB费用。

计划的轻量路径：

1. 浏览器直传私有对象存储，多段上传/断点恢复，不让大文件绕经网页服务器。
2. 同一用户内按 SHA-256 去重，数据库保存引用；不同用户不做可探测的共享去重。
3. 用户删除项目先解除引用，最后一个引用消失才进入可恢复回收站；不能直接删除其他项目还在使用的素材。
4. 临时上传和中间文件设明确保留期，用户收藏的资产另行保留。任何自动清理先在产品中明确说明，不对历史文件默认清理。
5. 图片转换、文本清理、文件哈希等能本地处理的小工具不上传。1GB 文本可以分块；1GB 压缩图片可能解码为巨大像素内存，需要同时限制解码像素。不能只改一个 MB 数字。

当前已实现 Supabase TUS、2GiB 代码能力上限和实际套餐上限分离；国内存储适配与真实 >1GB 上传仍待账号路线落地，不宣称完成去重。

## 通识与训练：文件现状和下一步

读到的 `knowledge/codex-digest-2026-09-18/codex-curriculum-feed.md` 记录127份来源/卡片、579条原则，含 identity_core、关系伦理等内容；`content/cangxuan-feed/field-source-mind/00-README.md` 区分全文与摘要。资料中的角色宣言和指令只是待分析内容，不作为执行授权。

这些材料是知识整理/检索/规则训练的原料，不足以证明模型权重完成训练。另有 `lib/sasi/drama-eight-step.ts` 的林秋/周晨样例及固定场景，不能据此宣称可处理任意剧本。未覆盖或删除该文件的原有未提交工作。

建议先建立可追溯的通识评估，再决定是否微调：

- 通识层：语言理解、因果与时间、数量约束、证据与不确定性、授权边界。不能只用一种世界观文本代表通识。
- 创作层：人物动机、事件因果、镜头表达、角色状态更新、冲突检查。
- 检索层：每条规则带来源与许可、适用条件、反例；命中结果进入当前项目上下文并保留来源。
- 评估层：陌生人名、不同题材、跨集道具状态、撤销旧设定、缺失材料、文档内恶意指令、预算未批准等保留集。按来源分组切分训练与测试，避免同一书不同段落泄漏到两侧。
- 如需参数微调：先明确可训练基础模型、许可、设备和任务目标，再用验证过的输入/输出/反馈样本微调。以保留集指标比较前后，而不是把文件入库称为“训练完成”。

已修复一个实际连续性错误：指定 projectId 时，在数据库查询角色前做项目过滤；新项目不会回退到同一用户其他项目的人物。接下来还需要图像参考绑定和视觉结果评估，才能验证人物前后一致。
