# 卡路里、提现与退款重构验收记录

## 用户能获得什么

- 拍照、批量图片、输入名称三种入口；每张图片可添加多种食物，份量可以清空、重填或输入小数。修改食物或份量后，旧结果立即失效。
- 13,359 条 USDA 基础食物资料和 2,127 条台湾食品营养资料。油条、蓝莓等进入真实数据检索，未找到的复合菜可按原料或包装营养表记录。缺失营养显示未知，不按零计算。
- 中文、英语、日语、韩语、法语、德语、西班牙语、葡萄牙语、阿拉伯语操作及建议；阿拉伯语采用从右到左布局。原始数据库条目的全部详细名称尚未逐条译成九种语言，保留原文以免把不同做法误合并。
- 结果同时给出营养、每种食物的数量、下一餐搭配建议和数据来源。建议用于一般饮食记录，不以一餐推断疾病、营养缺乏或要求补偿性节食。
- 余额提现按原支付渠道退款；人民币和美元分别记账。申请、支付渠道处理中、渠道确认完成、失败释放金额有不同状态，进入个人通知和右上角通知入口。
- 旧退款申请重新可见；迁移旧申请时，释放旧冻结与建立新冻结在同一事务完成。后续可继续处理或刷新原申请，不重复申请、不重复冻结。

## 架构与采用的经验

成熟工具把图片候选、食物检索、具体做法、份量、营养换算和建议分开。参考 [FatSecret 平台](https://platform.fatsecret.com/platform-api) 与 [图片识别接口](https://platform.fatsecret.com/docs/v2/image.recognition) 的职责划分；未接入其收费服务，也未复制其专有数据。

本次实现采用以下分层：

1. 本机图片候选：Food101 与 CLIP 分离文本、视觉编码器，多区域候选合并。图片本身不能精确测量克数，候选始终需确认。
2. 多语言名称和地域别名归一化；精确匹配、做法和来源信息共同供用户选择。
3. 可追溯营养资料：[USDA FoodData Central](https://fdc.nal.usda.gov/api-guide/) 的 CC0 数据，以及 [台湾食品营养成分资料集](https://data.gov.tw/dataset/8543)；提取脚本与来源清单在 `scripts/food-final`、`data/nutrition`。
4. 用户确认重量、统一单位换算、未知营养保留为空。建议与数值计算分离，可独立检查。
5. [CLIP MIT 许可](https://github.com/openai/CLIP/blob/main/LICENSE) 和固定模型修订、文件哈希；当前运行库由依赖管理，配套 JS/WASM 同版本并在本站提供，避免旧文件混装和海外运行库下载依赖。

这不是“全球任意食物均能准确识别”的证明。自制菜、遮挡和复杂拼盘仍需要补充食物或原料；目前未完成大规模独立图片准确率基准，不能把词表大小当识别准确率。

## 退款问题和修复

核实到此前的一笔 1 元申请停留在旧 `requested` 状态，没有支付渠道退款凭证，金额仍在退款冻结余额内。未在本次验证中实际发起或模拟到账。

修复了数据库函数变量与列同名冲突，以及钱包流水约束不允许提现事件的问题。新增客户端请求幂等键、旧申请唯一关联、四类钱包扣除已冻结本金的校验，并将旧退款计入原订单累计退款上限。

退款执行先认领保存的申请，再调用渠道。渠道返回后先保存凭证，再确认账本；确认失败保留处理中供补查。缺少渠道配置时保留待提交，不伪装成已向渠道送出。查询进度使用 [PayPal 查询退款](https://developer.paypal.com/api/payments/v2)、微信退款查询和支付宝退款查询，核对金额、币种与关联编号，不把定时查询变成再次退款。PayPal 未保存凭证且结果不确定时保留待核查，禁止盲目重新退款。

通知以用户归属查询，并以申请及状态构成事件键；已读持久化，状态变化产生新的未读通知。保留站内公告。提现页可主动查询原申请，定时任务继续核对待处理记录；实际自动更新频率取决于部署的调度配置。
