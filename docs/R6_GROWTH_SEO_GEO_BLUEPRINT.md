# 灵犀场 SEO + GEO + 增长工程总纲（R6）

目标不是“多写文章”，而是把真实需求变成可发现、可使用、可引用、可分享的产品入口。

## 增长飞轮
发现 → 记住 → 搜索 → 体验 → 结果 → 分享 → 再回来

## 7 个增长引擎
1. 奇闻发现：负责陌生流量。
2. 痛点搜索：把“PDF怎么压到1MB”“PDF怎么签字”“视频怎么转文字”做成任务入口。
3. Before/After：展示真实结果数字，禁止伪造。
4. 场景方案：求职文件包、合同处理包、自媒体处理包、资料整理包。
5. SASI 造物：一句话→网站；一句剧情→短剧；一本书→可追问知识。
6. 用户作品：真实案例、作品、挑战和评论区出题。
7. 分享增长：可选 Created with LINGXIFIELD、同款生成、模板/Remix、邀请额度。

## SEO：产品化搜索，不做内容农场
- 核心工具页：/tools/<slug>
- 场景页：围绕真实任务与限制，例如“PDF压到1MB”“微信发不出去的PDF怎么压”
- 每个场景页必须直接连接真实工具，不能只是1000字文章。
- 标题、H1、正文、结构化数据必须与页面可见功能一致。
- 不创建近义词垃圾页；相近意图合并成一个高质量页。

## GEO / AI Search
- 继续执行传统 SEO 基础：可抓取、canonical、hreflang、sitemap、真实标题与描述。
- 每个工具页提供：用途、输入、输出、限制、隐私模式、价格、真实例子。
- 让关键事实可机器引用：短句、表格、明确数字、更新时间。
- SoftwareApplication / WebApplication JSON-LD 只标注页面真实可见内容。
- 不伪造 FAQ 富结果。Google 2026 已停止 FAQ rich result，FAQ 可为用户阅读保留，但不作为富结果策略。
- 对 Microsoft/Bing：启用 IndexNow；监控 Bing Webmaster Tools 的 AI Performance / citations。
- 对 Google：监控 Search Console 的 AI / multimodal 表现；图片、视频和工具结果页统一实体描述。
- llms.txt 可作为辅助导航，不把它当排名捷径。

## 双域
- lingxifield.com = 全球 canonical 主域。
- lingxifield.cn = 中国访问域，页面真实可用，但通过 canonical 指向 .com，避免两份相同内容互相竞争。
- www 两域 308 到裸域。
- 如果未来希望 .cn 单独排名，必须做真正的中国区域内容/服务差异，再改为独立 canonical；不能复制同页同时索引。

## 9 语言
zh/en/ja/ko/fr/de/es/pt/ar。
任何工具进入 public surface 前必须有 9 语言标题；非中文语言不允许回退显示中文标题/中文简介。
阿拉伯语页面继续 RTL。

## 内容实验
每天两条足够：
- 1 条发现流量：科学/宇宙/自然/考古
- 1 条增长实验：痛点现场解决 / SASI造物 / 用户挑战 / 场景方案 / 搜索占位

核心内部原则：
不要告诉用户灵犀场厉害。给它一件麻烦事，让用户亲眼看着麻烦消失。
