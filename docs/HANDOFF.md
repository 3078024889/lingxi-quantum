## 三条不能动摇的原则

1. **创作时可以用AI，运行时不可以。** 例外只有三处真正接自由文本的
   功能：意识显化签到、灵犀提问、梦境解读——且AI只当解析器输出标签，
   不当写手输出成文。
2. **两层架构。** 结构层（出生数据，不变，可复算）× 状态层（自评+
   行为记录，会变）。报告是两者的乘积。绝不能用"重算出生数据"假装
   看见了成长——输入没变，结果数学上不可能变，那是欺骗。
3. **系统没有能力"感应"意识变化。** 只能把用户自己走过的路如实映
   回给他。加神秘性就掉进第五条纪律。

## 【扩展方案】知识库第二阶段：三个自由文本功能 + 法典思想的正确用法

### ⚠️ 首先：126 份法典的版权边界（这一条不能含糊）

法典是造翼者体系（James Mahu）的受版权保护作品。**知识库里不能出现
它的原文，也不能出现"换了几个词的复述"**——后者同样是侵权，而且更
危险，因为它看起来像原创。

但**思想、框架、概念结构不受版权保护**。可以做的是：
```
读法典 → 提取其中的概念骨架（例如"心的六种品质"这类框架）
       → 用完全自己的语言、自己的例子、自己的句子重新写
       → 写出来的东西必须能独立成立，不依赖读者读过原文
```
判断标准：把你写的段落给一个没读过法典的人看，他能不能读懂并用上。
能，就是原创表达；不能、需要靠原文才成立，就是改写，不能用。

**署名与出处**：可以在产品说明里写"体系扎根于造翼者与主权性积分态
教导"（这是事实陈述，站得住），但不能在节点内容里引用原文段落。

### 一、梦境解析知识库（优先级最高）

结构：
```
knowledge/dream/
  symbols.json     符号 → 释义（按语境分叉，不是一符号一固定答案）
  emotions.json    梦中情绪基调
  themes.json      主题（转换/追赶/失落/重逢…）
  combos.json      符号×情绪×主题的交叉释义 ← 真正的价值在这
```
关键设计：**同一个符号在不同情绪下含义不同**。蛇 + 好奇 ≠ 蛇 + 恐惧。
一符号一答案是最低级的做法，也是市面上所有解梦网站的做法。

AI 只做解析（输出符号/情绪/主题标签），文字全部来自这个库。
每解析出新符号 → 缓存 → 人工审定 → 沉淀进 symbols.json。
**词典是自己长出来的，三个月后就是别人复制不了的资产。**

### 二、意识显化签到知识库

签到不是记录，是**序列**。价值不在单次，在模式：
```
knowledge/manifestation/
  patterns.json    连续性模式（连续7天/断续/回归）
  frames.json      回应框架（按签到内容分类，不按情绪好坏分类）
```
硬规矩：**签到内容不做好坏评判**。用户写"今天很糟"和"今天很好"，
系统的回应结构应该是同一套——都是"被看见"，不是"被打分"。

### 三、提问灵犀知识库

AI 负责把问题归类，知识库提供回应骨架。
```
knowledge/inquiry/
  question-types.json   问题分类（关于关系/关于选择/关于卡住/关于意义）
  frames.json           每类的回应框架
```
硬规矩：**不替用户做决定**（第八条纪律）。回应框架必须是
"帮他看清楚他自己已经知道的东西"，不是"告诉他该怎么办"。

### 四、"变数"从哪里来（用户要的更强大的基石）

变数不是靠随机，靠这四层叠加：
```
1. 单维变体      同一分数带写 2–3 个变体（hash 决定，可复算）
2. 交叉组合      维度之间的关系，信息量最大的一层
3. 状态层        同一个人不同时期读到不同的话
4. 跨产品引用    ← 这一层还完全没做，潜力最大
```
**第 4 层说明**：用户如果同时买过生命韧性和桃花磁场，报告里可以出现
"你在关系里的模式，和你恢复能力的结构是同一套东西的两面"这类内容。
这是任何单一产品都给不出的深度，也是最强的复购理由。
需要新增 `knowledge/_cross/` 存放跨产品交叉节点。
