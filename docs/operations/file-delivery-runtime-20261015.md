# 文件保存与跨应用分享

## 用户问题与已确认的代码行为

用户报告：视频工具箱导出的 MP3 在 iPhone“文件”中可以播放，但从系统分享面板转发到微信后没有下一步。本机没有连接该 iPhone，不能据截图断定微信内部失败原因。

共用旧下载函数会根据微信等 User-Agent 自动调用 `navigator.share`，把 `AbortError` 视为分享成功，然后可能自动上传至临时存储。结果面板忽略返回值，用户无法区分保存、分享取消或临时预览。PDF 转图片、手写 DOCX、临时邮箱另有寿命仅 0.5—1.5 秒的独立 Blob 下载逻辑。

## 修改

- 本地保存与发送文件分开；本地保存不触发系统分享，也不自动上传。
- 发送前以 `canShare({files})` 检查文件能力，并从点击事件直接提交真实 `File`，避免等待编码、网络或模块加载后丢失用户激活。
- 区分不支持、取消、目标应用拒绝及系统接收；不显示未经确认的“微信发送成功”。扩展名补齐正确 MIME，长名称截短时保留扩展名，保留原始文件字节。
- 所有采用共用结果面板的工具增加发送入口；PDF 编辑器结果复用相同操作。音频可就地试听，长文件名及按钮在窄屏内换行。
- 合并 PDF 转图片的独立下载实现，手写 DOCX 与临时邮箱采用同一保存函数。Blob 下载链接保留五分钟；音频预览在结果替换或卸载时释放。
- PDF 转图片保留结果 ZIP 供重新保存与发送，错误提示标记为 alert；严格拒绝小数、倒序、超界及无效页码，失败与取消释放 PDF 和画布。
- 九国语言提供保存与微信附件路径说明。可选临时上传必须单独点击明确同意，需登录；签名链接有效十五分钟，持链接者可访问。不把它作为永久文件交付。

## 验证边界

`scripts/test-file-delivery-v91.cjs` 检查 MP3/PDF/PNG/MP4/ZIP/DOCX MIME、字节保留、保留扩展名、无隐式分享或上传、取消和拒绝、能力缺失及链接寿命。浏览器专项分别验证四类分享结果、真实下载、显式上传失败恢复、320 像素布局，以及视频工具箱实际提取的 MP3 试听与发送字节一致性。系统分享入口被隔离，未向真实联系人发送文件。

这不等于微信 iOS 真机已经验收。系统是否提供微信目标、微信是否接受并最终发送文件由手机系统与微信决定，网页无法获得朋友收件回执。参考 [W3C Web Share 规范](https://www.w3.org/TR/web-share/) 的文件能力检测、瞬时用户激活、取消/失败和系统交接语义；未复制其他平台私有实现。微信官方文档在本次工具中无法打开，因此不据此声称已完成原生微信接口接入。
