# 灵犀场小程序 5.7.6｜CNY 原生充值 + USD 官网充值

状态：源码候选已构建，等待 GitHub Actions 验收；不得提前上传微信或开启生产支付。

## 唯一充值入口

- **CNY**：小程序原生页面 `pages/cny-wallet/index`，使用微信虚拟支付。
- **USD**：小程序打开官网 `/ai-wallet?currency=USD`，使用官网 PayPal。
- **工具商品**：继续使用独立 `pages/pay/index` 与 `/api/wechat/mini/tool-pay/*`，不与余额充值混用。

## 本轮彻底清理

- 不再发布旧 `pages/balance`、`pages/recharge` 页面。
- 不再发布旧的余额充值缓存过期工具和支付错误工具。
- 旧的 website-only 余额充值拦截、旧充值函数和旧 API 命名不进入新发布包。
- 旧版 5.7.5 工作流不再作为本轮发布入口；新工作流只生成 5.7.6 ZIP，不上传微信、不提交审核、不部署生产站。

## 资金安全边界

- 小程序客户端的支付成功回调不直接入账。
- 服务端通过微信订单查询确认订单金额、环境、商品和订单号，再调用现有幂等入账流程。
- 同一账户最多保留一笔未完成的 CNY 原生充值订单；数据库事务锁负责并发预留。
- 旧客户端的 requestId 格式只用于识别已有订单，不会因此创建第二笔订单。
- 保留历史订单、微信回调验签、查单、退款处理、账本与幂等结算。
- 不按本地超时删除金融订单；未确认订单必须先由微信确认关闭。

## 账户资料

用户名保存按钮在手机端改为输入框与全宽保存按钮上下排列，输入框和按钮均使用明确的浅色样式，避免 WebView 默认黑色控件及裁切。

## 生产启用条件

后端 CNY 原生充值开关为 `WECHAT_MINI_VPAY_TOPUPS_ENABLED=true`，并要求 `WECHAT_MINI_VPAY_ENV=production`、微信虚拟支付配置完整、充值 SKU 已发布且通过真机验收。未满足条件时 API 必须 fail-closed，不得伪造可用状态。

## 发布验收

- GitHub Actions：源码审计、支付幂等审计、历史订单/退款审计、TypeScript、隔离构建、ZIP 完整性与 SHA-256。
- 微信开发者工具：导入 5.7.6 ZIP 后验证 CNY 原生支付、订单核验、到账、USD 官网跳转、账户用户名保存。
- 真机支付验证通过前，不开启生产充值开关，不提交微信审核。
