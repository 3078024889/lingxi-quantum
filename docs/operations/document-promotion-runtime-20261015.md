## PDF 元数据：正文与文档属性分开检查

截图封面中的作者、译者是页面正文，清理元数据不会删掉它们。原工具确实还有独立缺陷：只清空六个常用字段，遗漏日期、自定义 Info 字段、文档及页面 XMP；隐私清理还会重新写入软件名称。

下载并测试了 [W3C 公开样例](https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf)。为覆盖原文件不含的情况，另明确构造了带作者、日期、自定义属性及两处 XMP 的测试副本。旧实现留下这些属性，修复后重新打开输出核验 Info/XMP 为空。独立 PyMuPDF 对两组原件/输出逐页比较，文字及渲染像素相同。没有声称测试了用户未提供的原始《哥白尼》PDF。

现在三个清理入口复用一个实现；单文件入口显示清理前后字段、XMP 数量及重新打开核验结果。它不是正文涂黑、批注清理、附件清理或图片 EXIF 清理工具。

## 实际点击发现的其他缺陷

| 范围 | 原问题 | 修改与验证 |
|---|---|---|
| 图像式 PDF | 提高分辨率同时放大纸张物理尺寸 | 1×、1.5×、2× 输出保留原页面尺寸，逐一下载读取 |
| 四个结构工具 | 加密、解密、权限、网页优化写入 `output.pdf`，却读取另一文件名 | 统一内部输出名，真实 WASM 加密/解密/线性化验证 |
| 七个 qpdf 入口 | 资源被解析为 `file://` 本机路径；初始化失败会保留失败状态 | 本站绝对 URL、固定版本及哈希清单；失败销毁 worker、下次重建；实际断资源后重试 |
| 检查与书签 | 原查询接口与打包运行时不能可靠完成结构读取 | 独立解析页数、附件键名、嵌套及命名书签目的页；环与深度有界 |
| 附件 | 加入后刷新清空结果；内部文件名冲突；随后操作仍针对原始文件 | 固定内部附件名，保留外部键名；先核验新文件，再更新工作副本与结果；连续增删两种文件名 |
| 批量 PDF | 未选择扁平化时仍错误拒绝有表单的文件 | 仅对明确选择的扁平化检查最终表单状态；统一元数据清理 |

失败现场保存在 `pdf-structural-baseline.json`、`pdf-attachment-proof-baseline.json` 及其日志/trace。初始结构专项 4/8 失败；不是用“页面能打开”代替功能成功。修复后还检查了四种纸张、灰度真实像素、阅读布局/模式、打印与修改权限组合、原始页序、Unicode 属性等。

同类排查使用 `rg` 从一个 `runOne` 输出名不匹配扩展到所有输出名/命令参数，再检查包内 URL 解析。输出名问题为一个公共调用点影响四个入口；资源初始化为两个调用点影响七个入口。元数据三个清理调用点已统一；元数据编辑器的 setter 属于正常编辑，不作为删除类缺陷处理。新增真实浏览器用例与依赖补丁说明保留这些边界。

## 新增 PDF / 文档翻译

入口 `/tools/document-translate`，归入 PDF / 文档。支持 PDF、DOCX、PPTX、XLSX、ODT、EPUB、UTF-8 TXT/MD/SRT/VTT，九种界面与目标语言，支持术语表、停止、异常恢复。Office 保留容器结构、非文字成员、样式、公式和关系文件；不会先转 PDF 再冒充原格式。服务端按原 ID 检查完整译文，遗漏、重复、空值及替代字符均不作为成功结果。

PDF 提供原文＋译文对照及试用的原区域排版模式；保留纸张大小和背景图像，译文页以图像保存。扫描件先 OCR；旋转文字、无法放入原区域的长译文会停止。试用最多 200 页、40 MB，界面明确显示。Office 长译文可能改变分页或超出原有文本框，仍需在办公软件检查。没有承诺任意复杂文件零错译、零版式变化或译文 PDF 可搜索。

翻译使用现有 SASI 体验额度，`allowConnected:false`；额度不足或服务不可用时停止，不会自动切到付费账户。文件在浏览器解析，待译文字和术语表才发送服务器。未登录时显示登录入口并保留当前页文件。

测试中译文服务隔离，实际执行上传、解析、逐段替换、生成、下载和独立读取；这证明文件链路，不代表真实模型翻译准确度已验收。中、日、阿译文字体的实际 PDF 输出已用 PyMuPDF 渲染后目视检查。长篇学术公式、多栏表格和全语种语义准确度仍需专项真实语料验收。

参考 [BabelDOC](https://github.com/funstory-ai/BabelDOC) 与 [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next)。它们提供值得参考的版面分析和翻译流程，也有语言/版式适用范围及 AGPL 许可要求。本次没有将其代码拷入商业站点，也没有在 2 GB 服务器安装重型版面模型。

## 网址推广与 SASI

入口 `/tools/url-to-video`，归入视频。读取公开 HTTPS 网页，展示标题、描述、正文摘要供用户核对；使用已有固定 DNS/IP 的安全抓取器处理重定向与大小限制。网页文本只作为资料。用户选择时长、分辨率、平台与人群后带入 SASI，不因读取网址或跳转自动调用视频生成。

视频沿用已有 SASI 短剧报价与执行链路，没有第二套收费。24 秒平台费示例：720p 为 ¥4.80 / $4.80，1080p 为 ¥7.20 / $7.20；这两个币种数值来自现有价格配置，不是汇率换算，供应商费用另计，最终以确认页为准。读取网页免费。规格在资料之后单独保留，网页中的“50 集”或“720p”等文本不会覆盖用户所选规格。

研究了百度 [Hogee AI 制片组](https://cloud.baidu.com/product/Hogee/aidrama.html)、[度加 AI 剧公开服务范围](https://aigctv.baidu.com/platformAgreement)、[Creatify URL-to-Video](https://help.creatify.ai/en/articles/12435455-url-to-video) 与 [Topview Link to Video](https://www.topview.ai/link-to-video)。这些公开材料支持参考“资料→卖点→脚本→分镜→生成→合成”的工作流，不能证明任何视频都无需修改；未取得或声称取得它们的私有成片源码，也不能据此确认用户所称“百度搭子”的具体短剧产品。

SASI 的自动规划及逐集规划增加角色/服装/道具复用、镜头起止状态、视线方向、对白时长预算、字幕安全区和事实约束。它们是规划规则，不能替代对实际视频的角色一致性、口型、配音、字幕和转场验收。本次未花费调用视频供应商，网址入口的最终成片质量尚未认证；品牌素材与精确文字叠加也不宣称已自动完成。

关键词候选来自相关公开产品页面与本次搜索，如 `URL to video`、`AI ad generator`、`product video`、`PDF translation`、`remove PDF metadata`，用于已有功能的页面标题、说明与分类。没有全球用户私有搜索记录，也没有伪造搜索量、排名或获客效果。

免费安装 `seo-audit`、`content-strategy`、`copywriting` 三个 Codex 技能，来源 `coreyhaines31/marketingskills`，固定提交 `55ff469422c3592dac45bcad08dfb40221981c02`，保留 MIT 许可和哈希。这些是本机创作/审计技能，不冒充网站已新增的运行时执行器，也不提供免费视频算力。
