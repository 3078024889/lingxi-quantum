# 提现、原路退款与运营提醒

管理员入口：https://lingxifield.com/account/money-admin

提醒收件人与管理员登录邮箱均为 business@lingxifield.com。此邮箱截至实现时还没有网站账号，需使用网站现有注册登录功能建立账号。权限读取服务端数据库白名单，不读取用户可修改的角色信息。

## 用户操作

申请提现会保存申请并冻结金额，尚未向支付渠道发起退款。申请记录提供“确认退款”和“取消提现”。取消后原冻结金额恢复为可用余额；重复取消不会再入账。确认提交后，申请不能取消，因为渠道可能已受理。历史未提交的退款申请提供“取消退款”，已受理或已迁移的记录不能再次取消。

人民币与美元分别记账，退款按原支付渠道和原渠道币种进行；PayPal 以美元退款，即使历史订单对应人民币钱包也保留渠道金额。

## 管理员操作

看板分别显示微信支付、支付宝、PayPal 的待处理金额、资金不足涉及的退款金额和待用户确认申请。这里显示退款金额，不是支付平台实时商户余额或精确充值缺口。遇到资金不足，先在对应商户平台补资金，再点击“查询并继续原单”。用户尚未确认的申请不能由管理员代为提交。

新申请、处理中、完成、取消、失败，以及资金不足或人工处理事件进入通知队列。队列保存唯一事件编号，邮件使用固定幂等键；数据库只在邮件服务返回消息编号后记录“已发送”。“已发送”表示邮件服务受理，不代表已进入收件箱。

邮件沿用现有 RESEND_API_KEY。发件人优先 LINGXIFIELD_MONEY_FROM_EMAIL，其次 LINGXIFIELD_SUPPORT_FROM_EMAIL，默认 support@lingxifield.com，需使用邮件服务已验证的域名。未配置时保留队列，不显示发送成功；发送失败会退避重试。自动发送每轮最多尝试 10 次。管理员点重试后，将失败记录立即放回发送队列并重置本轮次数；正在发送的记录保留调用锁，不会被主动重试覆盖。看板可查看配置状态和发送记录。实际邮箱送达尚未以真实收件验证。

node scripts/test-money-operations.cjs：验证服务端管理员白名单、伪造角色拒绝、未确认申请不发起退款、三渠道资金不足分类、缺少邮件配置保留队列、渠道币种金额、幂等键、发送回执和失败重试。全部使用模拟传输。

Playwright money-operations.spec.ts：桌面与手机验证 CNY/USD 金额选择、唯一付款入口、取消、确认提交、取消冲突提示、历史退款按钮、管理员看板与非管理员拒绝。
