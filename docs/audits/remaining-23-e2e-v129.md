## 工程要求

1. 同一个确切代码提交 SHA 上执行桌面/移动 Playwright，提供每项 fixture、操作脚本、输出文件、真实解析断言与 CI 日志。
2. 对需要第三方 API 或实际付款的路径：先用隔离假服务验证权限与失败恢复，再以有授权的真实沙盒/生产商户流水核对；**模拟付款不能认定真实付款成功**。
3. 用户机密文件不用于自动化；使用自己创建的合成样本。对人像、音频与内容翻译只用已授权素材，确保隐私。
4. 页面仍可访问不能认定为验收完成；上线必须确认 GitHub `main` 和 Vercel `production` 的 SHA 一致，域名真实可访问。不能绕过 Vercel 配额，也不能把 CI 成功等同于生产竣工。
5. 25 → 23 是因新增 `pdf-to-xlsx` 和 `privacy-cleaner` 完整实测场景登记，仍待最新 PR #106 CI 执行结果证实。
