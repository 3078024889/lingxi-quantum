核查日期：2026-11-02

## 实施

- PDF V116 的图片/签名选择对象拖拽、缩放手柄改为捕获当前手柄的 pointer events，不再捕获整个画布，降低拖拽过程中目标变化导致手势丢失的风险。
- 手机缩放手柄 32×32 CSS 像素、旋转手柄 32×32；桌面缩放手柄 20×20。保留原生指针和键盘方向键操作。
- 用 `tests/final-closure/pdf-editor-save-reopen-v123.spec.ts` 构造 PDF 中真实原文、上传新 PNG、在同一页面直接编辑，模拟**无真实扣款**的报价/支付结果、调用现有权限消费接口的隔离桩，完成下载。用 pdf-lib 再次读取页数和尺寸，用 PDF.js 验证底层原文仍存在与图片绘图操作存在。
- 继续跑 `pdf-editor-visual-quality-v116.spec.ts` 桌面/手机场景，以断言缩放手势真实改变组件宽度，不把失败测试删掉。

## 精确使用边界

真正可删除 PDF 原文字内容的编辑引擎需要修改内容流、字体子集、对象引用，还要处理 OCR、签名、透明图像等；当前 pdf-lib + PDF.js 只能做到覆盖后添加对象，不能承诺敏感字节被彻底移除。需要删除敏感信息时应使用真实 PDF 脱敏工具，并通过结果文本/图片对象再解析验证。

在交付/生产门禁全部通过并合并到 main 与正式生产 SHA 之前，不标注正式竣工。
