# SQL 历史迁移文件（已归档）

这里的每个 `SQL-vXXX-*.sql` 都已经合并进 `supabase/schema.sql`，内容
完全覆盖，不需要再单独执行。保留在这里只是作为历史记录——如果以后
排查某张表/某一列是什么时候、为什么加的，这些文件里的注释里有当时
的报错信息和原因分析，比 git log 更好读。

**如果你的线上 Supabase 项目已经执行过这些文件**（大概率已经执行
过，不然产品早就报错了），可以放心整个删除这个文件夹——
`supabase/schema.sql` 现在是唯一需要维护、可重复执行的版本。

**如果不确定线上是否都执行过**，最安全的做法是把新版
`supabase/schema.sql` 完整地在 Supabase SQL Editor 里再跑一次——
里面所有语句都用了 `if not exists` / `add column if not exists`，
已经存在的表和列会被跳过，不会报错、不会丢数据。跑完之后再删这
个文件夹就绝对安全了。
