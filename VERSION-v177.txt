【发生了什么——从你发的构建日志开始查起】
你发的构建日志，关键的一行是：
"Error occurred prerendering page '/practice'"
"@supabase/ssr: Your project's URL and API key are required..."
意思是：Next.js在构建阶段，试图把 /practice 这个页面提前生成好静态
HTML（这样访问的时候不用现算，加载更快），生成的过程中，代码执行到
了一处需要Supabase的地方，但构建这个阶段拿不到需要的环境变量，直接
报错，导致 `npm run build` 这个命令返回失败——**只要这个命令失败，
Vercel 就不会有新的部署上线**，会继续把上一次成功构建的版本，原样
提供给所有访问者。

顺着这条线查下去，找到了根源：v169 那次，给"修炼技术"首页
（/practice）新加了"修炼心得记录"这个组件（PracticeJournal.tsx），
里面有一行 `const supabase = createClient()`，写在了组件最顶层——
这行代码会在"每一次渲染"都执行，包括 Next.js 构建阶段对这个页面做
服务器端预渲染的那一次也会执行到。构建这个阶段拿不到运行时才有的
环境变量，一碰到这行代码就直接抛错，整个构建失败。

**这意味着：从 v169 部署的那一刻起，很可能之后每一版（v170到v176）
的构建都在失败，Vercel 一直在悄悄提供 v169 之前那个能成功构建的旧
版本**——你这段时间测试到的螺旋场、灵犀提问、429限流、塔罗牌这些
问题，很可能根本不是"这些修复没生效"，是这些修复从来没有真正被
部署上线过。这也解释了刚才提到的"梦境解析那儿也是429"——如果一直
在跑的是v169之前的旧版本，那v175里对429限流的修复（换成并发数更
宽松的glm-4-air），自然也没有真正生效。
