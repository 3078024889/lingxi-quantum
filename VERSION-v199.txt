【二、"创建订单失败"——找到真正原因了】
supabase/schema.sql、app/api/pay/create/route.ts
- 真正原因：orders 表里 submission_id 这一列，最早只给生命图谱一个
  产品设计，用外键强制关联到 life_map_submissions 这一张表。后来
  陆续加了关系共振、摇签、塔罗三张牌阵，这些产品的订单一下单，
  submission_id 指向的其实是另外的表（qian_submissions、
  tarot_reading_submissions），外键校验直接不通过，插入失败——
  这才是"点解锁没反应/创建订单失败"的根本原因，不是玄学，是外键
  设计的问题。
- 这次把这个外键约束去掉，改成普通字段；同时修了下单接口里"查
  提交人姓名"这段代码，之前也是写死只查生命图谱那张表，现在按
  产品类型对应到正确的表。

【需要在 Supabase SQL Editor 里单独执行这一条】
alter table public.orders drop constraint if exists orders_submission_id_fkey;

这条本身也包含在最新的完整 schema.sql 里，如果你想省事，直接把
上面发过的完整 schema.sql 再跑一遍也可以，效果一样。

【三、新增：独立的场域入口页】
components/EntryGate.tsx（新文件）
- 之前把"灵犀场·意识显化系统"这段介绍直接改进了首页第一屏本身，
  这是我理解错了你的要求——你要的是"打开网站，先看到一个只有

- 这次单独做成一层，盖在首页最上面（不是新开一个网址，避免"首页
  到底是哪个地址"这种分享链接的复杂度）：只有名字+介绍+"进入场域"
  按钮，点击后触发九彩螺旋场动效，停留一下，再淡出，显现出你现在
  已经看到的首页。同一次浏览器会话里，只会看到一次（用
  sessionStorage记住"已经进过场"，刷新/站内跳转不会重复出现，
  关掉浏览器重开会再看到一次）——如果想要"每次打开首页都重新
  展示"，告诉我，去掉这个记忆判断就行。
- 首页本身第一屏的文案做了区分，不再跟入口页说同一段话——入口页
  负责"介绍这是什么"，首页第一屏变成"你已进入灵犀场"这种承接
  语气，避免用户点了进入场域之后，看到的还是一模一样的介绍语。
